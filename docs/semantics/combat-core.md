# Semantics: combat core (execution, hooks, damage, turns, piles)

Append-only. One fact per bullet, with a decomp reference (`ref/<path>:<line>`) and the task id that found it. Index: `docs/semantics.md`.

## Combat loop / execution model (R1)
Full detail in `docs/specs/combat-loop.md`. Paths are under `ref/decomp/`.
- Effects are nested depth-first `await` chains; there is no effect queue. The `GameAction` queue only carries player input (play card, use potion, end turn, hook-choice resume). (R1) `MegaCrit.Sts2.Core.GameActions/GameAction.cs:12-28`, `MegaCrit.Sts2.Core.GameActions/ActionExecutor.cs:123`
- Hook listener lists are snapshotted at the first `MoveNext`, but each entry is re-checked with `Contains` when it is yielded, so models removed mid-dispatch are skipped. (R1) `MegaCrit.Sts2.Core.Combat/CombatState.cs:411-486`
- Listener order is allies then enemies; per creature: powers (application order), then relics, potions, orbs and cards in pile order Hand, Draw, Discard, Exhaust, Play (each card followed by its Affliction, then Enchantment); enemies: powers then the monster model. (R1) `MegaCrit.Sts2.Core.Combat/CombatState.cs:411-470`, `MegaCrit.Sts2.Core.Entities.Players/PlayerCombatState.cs:70-80`
- Combat hooks go silent (yield no listeners) once combat `IsOverOrEnding`, evaluated once when the dispatch starts. `IsEnding` turns true the instant the last primary enemy's HP is 0, before `Kill` runs. (R1) `MegaCrit.Sts2.Core.Hooks/Hook.cs:53`, `MegaCrit.Sts2.Core.Combat/CombatManager.cs:417`
- Win/loss is evaluated only in `CheckWinCondition` (after every GameAction, after each enemy move, at end-turn phase steps). `Kill` only sets `PendingLoss` when all players die; a loss fires no `AfterCombatEnd` hooks. (R1) `MegaCrit.Sts2.Core.Combat/CombatManager.cs:1387`, `MegaCrit.Sts2.Core.GameActions/ActionExecutor.cs:170`
- Player turn start order: `BeforeTurnStart` snapshot, `BeforeSideTurnStart`, enemy `RollMove`, block clear (skipped for a player on turn 1), `AfterBlockCleared` (always fires), energy reset, `BeforeHandDraw`, `ModifyHandDraw(5)`, draw, `AfterPlayerTurnStart`, `AfterSideTurnStart`, auto-pre-play phase. (R1) `MegaCrit.Sts2.Core.Combat/CombatManager.cs:688-924`
- Enemy next-move `RollMove` (MonsterAi rng) happens at the start of the player turn, not right after the enemy acts. A second roll before the first move is performed is a no-op. (R1) `MegaCrit.Sts2.Core.Combat/CombatManager.cs:739-745`, `MegaCrit.Sts2.Core.MonsterMoves.MonsterMoveStateMachine/MonsterMoveStateMachine.cs:60`
- End turn has two phases: phase one runs `BeforeSideTurnEnd`, then Ethereal exhaust and turn-end-in-hand cards, then `BeforeFlush`. Phase two flushes the hand with one batched `Add`, so there is no `AfterCardDiscarded` for the flush, then `AfterFlush` and `AfterSideTurnEnd(Player)`. Queued card plays are cancelled when phase one starts. (R1) `MegaCrit.Sts2.Core.Combat/CombatManager.cs:1437-1819`
- A card's result pile is decided before `OnPlay` (`ExhaustOnNextPlay` is consumed then). The card stays in the Play pile through all of `OnPlay` and `AfterCardPlayed`, then moves via `CardPileCmd.Add` (not `CardCmd.Discard`), so a played card fires no `AfterCardDiscarded`. (R1) `MegaCrit.Sts2.Core.Models/CardModel.cs:1858-2019`
- Damage pipeline per target: `ModifyDamage` (additive pass, multiplicative pass, cap pass over all listeners), `BeforeDamageReceived`, block (taken from `PetOwner`'s block if the target is a pet, so hitting Osty spends the Necrobinder's block), `ModifyHpLost` (BeforeOsty), Osty redirect, `ModifyHpLost` (AfterOsty), `LoseHpInternal`. Kills run after all targets and hits of that `Damage` call. (R1) `MegaCrit.Sts2.Core.Commands/CreatureCmd.cs:276-430`
- Damage and block are C# `decimal` with no rounding until an `(int)` cast, which truncates toward zero: HP loss, `Block -= (int)min(Block, amount)`, block gain, and power amount offsets. Damage 5.25 into Block 10 removes 5 block and the 0.25 is lost. (R1) `MegaCrit.Sts2.Core.Entities.Creatures/Creature.cs:431-466`, `MegaCrit.Sts2.Core.Commands/PowerCmd.cs:240`
- A multi-hit attack runs one full `CreatureCmd.Damage` (all hooks) per hit, and picks a random target per hit from `Rng.CombatTargets`. (R1) `MegaCrit.Sts2.Core.Commands.Builders/AttackCommand.cs:551-669`
- Selections skip the choice when the options are empty, or when `!RequireManualConfirmation && count <= MinSelect` (the whole list is returned). X-cost is auto-captured from remaining energy; there is no in-combat X prompt. (R1) `MegaCrit.Sts2.Core.Commands/CardSelectCmd.cs:479-483,840`
- All combat RNG streams are run-scoped (`new Rng(seed, snake_case(name))`) and persist across combats. `Rng.Chaotic` is cosmetic only. (R1) `MegaCrit.Sts2.Core.Runs/RunRngSet.cs:139-143`
- `CombatHistory` records only a subset of events (no shuffles, flush discards, HP/block loss, RNG draws, hook boundaries or decisions), so it is not a sufficient oracle trace. (R1) `MegaCrit.Sts2.Core.Combat.History/CombatHistory.cs`

## Combat M0 (C1)
Paths are under `ref/decomp/MegaCrit.Sts2.Core.`.
- The reshuffle's `StableShuffle` sorts by `CardModel.CompareTo`: `ModelId` (category, then entry, both ordinal; e.g. `BODYGUARD < DEFEND_NECROBINDER < STRIKE_NECROBINDER < UNLEASH`), then `CurrentUpgradeLevel`. (C1) `Models/CardModel.cs:2272-2294`, `Models/AbstractModel.cs:96-107`, `Models/ModelId.cs:42-50`
- An attack built from a `CalculatedDamageVar` (Unleash) still uses `AttackCommand.DamageProps` (default `Move`); the var's own props are not passed to `Damage`. (C1) `Commands.Builders/AttackCommand.cs:127,201-205,669`
- `CardPileCmd.Add` to a combat pile is a no-op while `IsEnding`, so a card that kills the last enemy stays in the Play pile. (C1) `Commands/CardPileCmd.cs:379`, `Models/CardModel.cs:1989-2005`
- A new monster creature (Osty included) starts at `MaxInitialHp`/`MaxInitialHp`, so Osty is alive at 1/1 when `DieForYouPower` is applied, before `SetMaxHp`/`Heal`. (C1) `Entities.Creatures/Creature.cs:347-361`, `Commands/OstyCmd.cs:65-78`
- `WasBlockBroken`/`WasFullyBlocked` read `originalTarget.Block`, not the block holder's. A hit aimed at Osty that spends any of the owner's block reports `WasBlockBroken` even if block remains. (C1) `Commands/CreatureCmd.cs:294-295`
- `DieForYouPower.ShouldAllowHitting` returns `creature.IsAlive` for every creature, and `CanReceivePowers` uses that guarded hook, so while Osty's power exists no dead creature can receive powers. (C1) `Models.Powers/DieForYouPower.cs:35-38`, `Entities.Creatures/Creature.cs:309-322`
- `Hook.AfterEnergyReset` is guarded and runs a full `AfterEnergyReset` pass, then a full `AfterEnergyResetLate` pass. (C1) `Hooks/Hook.cs:515-527`
- `EndEnemyTurn` calls `SwitchSides` unless `IsCombatEnding`, which is false once combat is no longer in progress, so a win or loss processed during the enemy turn still switches sides (round and turn counters advance after the end). The port mirrors this. (C1) `Combat/CombatManager.cs:1073-1091,417-422`
- In a redirected lethal hit, the `Kill` batch lists Osty before the owner, so Osty dies first. (C1) `Commands/CreatureCmd.cs:296-311,393-430`
## Hook surface (C4)
Paths are under `ref/decomp/MegaCrit.Sts2.Core.`. Per-hook call sites: `docs/specs/content-api.md`.
- `ShouldPowerBeRemovedOnDeath`, `ShouldCreatureBeRemovedFromCombatAfterDeath`, `ModifyUnblockedDamageTarget`, `AfterBlockBroken`, `AfterDamageGiven`, `AfterCardPlayed`, `AfterDiedToDoom` and `ShouldStopCombatFromEnding` iterate the combat listeners directly (no guard); `BeforeCombatStart`, `AfterCardChangedPiles`, `ModifyDamage`, `ModifyHpLost`, `BeforeDamageReceived`, `AfterDamageReceived`, `AfterCurrentHpChanged`, `BeforeDeath`, `ShouldDie`, `AfterDeath` and `AfterPreventingDeath` take `IRunState` (no guard); every other combat hook uses the guard. (C4) `Hooks/Hook.cs`
- The guard does not apply while combat is starting (`IsStarting`, true from the turn state's creation until `IsInProgress` is set), so hooks fired by a monster's `AfterAddedToRoom` (Inklet applying Slippery) reach their listeners. (C4) `Hooks/Hook.cs:53-63`, `Combat/CombatManager.cs:592-593`, `Combat/CombatTurnState.cs:96`
- The `AfterModifyingX` hooks reach only the listeners that changed the value: block, damage and power-given by `!= 0` / `!= 1` per pass, hand draw by `(int)`, HP loss by `decimal.Truncate`, play count and received power by any change; a listener counts once even if it changed both passes. (C4) `Hooks/Hook.cs:661-851,1322-1352,1692-1773,1896-1939`
- `ModifyDamage` has a third, cap pass: the lowest `ModifyDamageCap` so far caps the running value when it is below it. (C4) `Hooks/Hook.cs:2547-2563`
- In `CreatureCmd.Damage` the overkill sent back to the original target after an Osty redirect goes through `ModifyHpLost(AfterOsty)` again (with its `AfterModifying` hook), and nothing is lost when it is 0. (C4) `Commands/CreatureCmd.cs:302-311`
- `ShouldDie` is skipped when the creature's max HP is 0; a prevented death runs `AfterDeath(wasRemovalPrevented: true)`, then the preventer's `AfterPreventingDeath`, then retries if the creature is still dead (an exception after 10 tries). A dead player's relics, potions and cards keep listening until after its Osty is killed (`DeactivateHooks`); `HealInternal` reactivates them on revival. (C4) `Commands/CreatureCmd.cs:514-602`, `Entities.Players/Player.cs:861-875`, `Entities.Creatures/Creature.cs:478-487`
- `PowerCmd.Apply` runs `BeforePowerAmountChanged`, `ModifyPowerAmountGiven` (only if the applier is still in combat), `ModifyPowerAmountReceived` and `BeforeApplied` with the modified amount; `ApplyInternal` adds nothing for a zero amount (a debuff Artifact blocked), but `AfterModifyingPowerAmountReceived` still runs; `AfterApplied` and `AfterPowerAmountChanged` need a non-zero amount. (C4) `Commands/PowerCmd.cs:105-161`, `Models/PowerModel.cs:572-581`
- `CardPileCmd.Add` of a batch moves every card first (each followed by `AfterCardEnteredCombat` if it had no pile), then fires `AfterCardChangedPiles(+Late)` per card whose pile type changed; it is a no-op for a dead owner or outside a live combat. The reshuffle and the hand flush are one batch each, so a reshuffle fires `AfterCardChangedPiles` only for the discard-pile cards. (C4) `Commands/CardPileCmd.cs:373-545,1076-1136`, `Combat/CombatManager.cs:1785-1820`
- A manual play moves the card from hand to the Play pile with `AfterCardChangedPiles(Hand)` and nothing else (skipped once combat is over or ending), and `AfterEnergySpent` fires before it even for a 0 cost. (C4) `Commands/CardPileCmd.cs:830-866`, `Models/CardModel.cs:1807-1834`
- `CheckForEmptyHand` (`AfterHandEmptied`) runs after a manual card play, after a potion use and on entering the auto-pre-play phase; it needs the combat in progress, no card or potion effect running and an empty hand. (C4) `Combat/CombatManager.cs:1171-1177,859-866`, `Models/CardModel.cs:2006`, `Models/PotionModel.cs:351`
- `DoTurnEnd` exhausts the Ethereal hand cards first, then resolves the `HasTurnEndInHandEffect` cards (Debt, Infection) in hand order: `CardPileCmd.Add` to Play, `OnTurnEndInHand`, then exhaust if Ethereal else discard bottom. Its waits are instant in non-interactive mode, so each card resolves fully before the next. (C4) `Combat/CombatManager.cs:1599-1690`, `Commands/Cmd.cs:36-44`
- `EndCombatInternal` runs `AfterCombatEnd`, then the player's teardown (`Player.AfterCombatEnd`: powers removed without callbacks, piles and pets cleared, all block lost), then `AfterCombatVictoryEarly` and `AfterCombatVictory`, which therefore see only relics, potions and the surviving allies' powers. (C4) `Combat/CombatManager.cs:1297-1326`, `Entities.Players/Player.cs:837-842`, `Entities.Players/PlayerCombatState.cs:142-151`
- `ShouldStopCombatFromEnding` is part of `IsCombatEnding`: with no living primary enemy, combat still is not ending while any listener votes to stop it. (C4) `Combat/CombatManager.cs:417-435`
- `ShrinkPower.AfterSideTurnEnd` calls `PowerCmd.Decrement`, not `TickDownDuration`, so the skip-tick rule does not apply to a finite Shrink; the P1 note and the backlog item that asked for `tick_down_duration` were wrong, and the port keeps `Decrement`. (C4) `Models.Powers/ShrinkPower.cs:80-86`
- `FrailPower` multiplies the owner's powered card/monster-move block (`IsPoweredCardOrMonsterMoveBlock`, the same test as `IsPoweredAttack`) by 0.75 and ticks down after the enemy turn; `SlipperyPower` caps the owner's HP loss at 1 in `ModifyHpLostAfterOsty` and decrements in `AfterDamageReceived` when the hit cost it HP. 30 seeds each of `FlyconidNormal`, `RubyRaidersNormal` and `InkletsNormal` match. (C4) `Models.Powers/FrailPower.cs`, `Models.Powers/SlipperyPower.cs`, `ValueProps/ValuePropExtensions.cs:5-22`
- `RubyRaidersNormal` draws three `NextItem`s over the raiders not yet picked, in the dictionary's insertion order (Axe, Assassin, Brute, Crossbow, Tracker); `FlyconidNormal` spawns a medium slime (`NextItem` over Leaf, Twig) then the Flyconid; `InkletsNormal` spawns three Inklets, the middle one `MiddleInklet` (opens with Whirlwind). Inklet's `INIT_RAND` state is built but unreachable. (C4) `Models.Encounters/RubyRaidersNormal.cs`, `Models.Encounters/FlyconidNormal.cs`, `Models.Encounters/InkletsNormal.cs`, `Models.Monsters/Inklet.cs`

## Engine gaps (C6)
Paths are under `ref/decomp/MegaCrit.Sts2.Core.`.
- `PowerModel.InitInternalData` gives each instance private data. `VigorPower` remembers the first powered attack of its owner whose `ModelSource` is a card or nothing (`commandToModify`) and the amount at its start; that attack gets `+Amount`, other cards' damage during it gets nothing, and after it Vigor drops by the remembered amount. `commandToModify` is never cleared, so a surviving instance gives no bonus to a later attack from another card. Attacks need an identity for this (`AttackCommand` compared by reference). (C6) `Models.Powers/VigorPower.cs`, `Models/PowerModel.cs:520-534`
- `PotionCmd.TryToProcure` (no slot index): `ShouldProcurePotion`, then the first empty slot (`IndexOf(null)`), then `AfterPotionProcured`; a full belt fails silently. `PotionCmd.Discard` empties the potion's slot, then `AfterPotionDiscarded`. (C6) `Commands/PotionCmd.cs`, `Entities.Players/Player.cs:628-706`
- `PlayerCmd.GainGold`: `ModifyGoldGained` (a modifier changed `(int)` gold), `AfterModifyingGoldGained`, then for a positive amount `Gold += (int)amount` and `AfterGoldGained`, which reaches run-level listeners only (`IterateHookListeners(null)`). `LoseGold` is `Gold = max(0, Gold - (int)amount)` with no hooks. Necrobinder starts with 99 gold. (C6) `Commands/PlayerCmd.cs:143-206`, `Hooks/Hook.cs:481,736,1634`, `Models.Characters/Necrobinder.cs:34`

## Last engine gaps (C11)
Paths are under `ref/decomp/MegaCrit.Sts2.Core.`.
- `TargetingRandomOpponents` makes an attack multi-targeted (`GetPossibleTargets` is `GetOpponentsOf(attacker)` for a card or Osty source) and randomly targeted: per hit, after the living-target filter, one `NextItem` on the attacker's (or its pet owner's) `Rng.CombatTargets`, and the hit damages only that creature. Duplicates are allowed outside tests. A `RandomEnemy` card takes no target (`IsValidTarget(null)` is true for every type but `AnyEnemy`/`AnyAlly`). (C11) `Commands.Builders/AttackCommand.cs:163-180,322-339,603-618`, `Models/CardModel.cs:1762-1784`

- `Player.PopulateCombatState` clones every deck card into the draw pile and sets the clone's `DeckVersion` to the deck card; `AfterCloned` clears `DeckVersion`, so a clone or generated card has none. The clone copies the deck card's saved properties (`TheScythe`'s `CurrentDamage`, `IncreasedDamage`). (C11) `Entities.Players/Player.cs:806-814`, `Models/CardModel.cs:1220-1232`
- `CardCmd.DiscardAndDraw(cards, n)`: discards each card in turn (`AfterCardDiscarded`), draws `n`, then autoplays the cards that were Sly; `GamblingChip` and `GamblersBrew` both call it with the selection's size. (C11) `Commands/CardCmd.cs:172-205`, `Models.Relics/GamblingChip.cs`

## Unsupported stops and instanced powers (C12)
- Generating, or transforming into, a card the engine does not port stops the combat with `Interrupt::Unsupported` (`Status::Unsupported`, `RunDecision::Stopped`) instead of panicking. `GetDistinctForCombat` shuffles the whole filtered pool before it creates the picks, and `GetForCombat`/`TransformToRandom` draw each pick before creating it, so the RNG has advanced exactly as the game's when the stop happens. A Status or Curse transform (pools not modeled) stops before any draw. (C12) `Factories/CardFactory.cs:119-152,165-212`
- `PowerCmd.Apply<T>` returns the instance: the new one (even when it never joined the target, a detached instance), or the stacked one unless `ModifyAmount` returned a new amount of 0. `ModifyAmount` returns the new amount, not the change. (C12) `Commands/PowerCmd.cs:38-60,219`
- `FindExistingInstanceForStacking`: `None` stacks onto `GetPower(id)`, `Instanced` never stacks, `InstancedPerApplier` stacks onto the instance with the same applier. New instances are appended to `_powers` (`ApplyPowerInternal`), so hooks fire per instance in application order. Instanced powers in Act 1: Automation, Panache, RollingBoulder, TheBomb, ToricToughness (and Oblivion per applier). (C12) `Commands/PowerCmd.cs:168-178`, `Entities.Creatures/Creature.cs:606-618`
- `ModifyCardPlayResultLocation` runs after `GetResultLocationForCardPlay` and before `GeneratePlayCount`; the modifiers get `AfterModifyingCardPlayResultLocation` directly (not through `Hook`). `CardPlay.ResultPile` is the modified pile; the card then goes to that pile at the modified position. (C12) `Models/CardModel.cs:1881-1886,1980-1996`
- The referee cannot play `RollingBoulder`: `RollingBoulderPower.AfterPlayerTurnStart` references `GodotObject.Connect` (its VFX branch), missing from sts2-cli's Godot stubs, so the method throws `MissingMethodException` when compiled whatever the `TestMode` branch, and the referee's combat turn loop dies. The diff harness never plays it (`REFEREE_BROKEN_CARDS`). (C12) `Models.Powers/RollingBoulderPower.cs`
- Extra turns (C14): at the end of the player's turn phase two, `SwitchFromPlayerToEnemySide` clears `PlayersTakingExtraTurn`, adds every player for whom `Hook.ShouldTakeExtraTurn` (any listener says yes, combat-guarded) holds, calls `SwitchSides`, then `Hook.AfterTakingExtraTurn` for each of them. With a non-empty list `SwitchSides` keeps/sets `CurrentSide = Player`, increments each of those players' `TurnNumber` and does not increment `RoundNumber`; the turn loop then runs the next `StartTurn` straight away (no enemy turn). The list stays set through the extra turn itself and is re-evaluated at its end, so a second stack gives another extra turn. In that `StartTurn` the creatures starting the turn are the extra-turn players' creatures only (not Osty), and the enemies' `PrepareForNextTurn`/`RollMove` is skipped; `RampartPower` and `PaelsEye` are the other readers (neither ported). Engine: `Player::extra_turn`, `turn.rs::switch_from_player_to_enemy_side`. (C14) `Combat/CombatManager.cs:688-760,1825-1895`, `Hooks/Hook.cs:1232,2465`
- `AmbergrisPower` (hidden, `IsVisibleInternal` false): `ShouldTakeExtraTurn` when `Amount > 0` and the player is its owner; `AfterTakingExtraTurn` decrements it (removed at 0). The `Ambergris` potion (AnyTime, `AnyPlayer`) heals `MaxHp * 50 / 100` and, only while combat is in progress, applies 1 `AmbergrisPower` with the player as applier. (C14) `Models.Powers/AmbergrisPower.cs`, `Models.Potions/Ambergris.cs`
- Power card source (C14): `PowerCmd.Apply`/`ModifyAmount` pass the applying card (`cardSource`) to `BeforePowerAmountChanged` and `ModifyPowerAmountGiven*`; every `PowerCmd.Apply` in `Models.Cards` passes `this` (`Hibernate` passes `cardPlay.Card`, the same card), while potions, relics, powers and monsters pass null. Only `UnsettlingLamp` reads it. Engine: `PowerQuery::card`, `Engine::apply_power_from_card`; cards that apply a power to an enemy use it. `PowerModel.IsVisible` is `IsVisibleInternal` for an enemy target (and for a not yet applied power); `AmbergrisPower` is the only hidden power in the Necrobinder Act 1 set. (C14) `Commands/PowerCmd.cs:105-260`, `Models/PowerModel.cs:148-167`

## DamageReceived history and Fatal (C18)
- `CreatureCmd.Damage` logs one `DamageReceivedEntry` per `DamageResult` (Osty redirects give two) in the per-target loop, right after the results are built and before `AfterBlockBroken`/`AfterDamageGiven`/`AfterDamageReceived`; fully blocked and killing results are logged too, and nothing is logged once combat is not in progress or is ending. The entry's actor is the receiver; it keeps `Result` (incl. `Props`), `Dealer` and `CardSource`. Spite = any entry this turn with receiver == owner and `UnblockedDamage > 0`; TearAsunder counts those over the whole combat (`1 + count`). (R1) `Commands/CreatureCmd.cs:316-320`, `Combat.History/CombatHistory.cs:78`, `Models.Cards/Spite.cs`, `TearAsunder.cs`
- Fatal (Feed, HandOfGreed, TheHunt): `target.Powers.All(p => p.ShouldOwnerDeathTriggerFatal())` is read before the attack; then `Results.Any(WasTargetKilled)`. `MinionPower` and `ReattachPower` veto it. (R1) `Models.Cards/Feed.cs:38`
- `Hook.ModifyDamage(target null, dealer owner, dmg, Move, otherCard, cardPlay null, All)` (Thrash) already works with `hooked().modify_damage(DamageQuery { target: None, card: Some(other), .. })`; no signature change was needed. (R1) `Models.Cards/Thrash.cs:70`

## Orbs (C16)

## Stars, Forge and the Regent (C17)
Paths are under `ref/decomp/MegaCrit.Sts2.Core.`. Spec: `docs/specs/regent.md`; engine: `combat/star_cost.rs`, `combat/commands/stars.rs`, `combat/commands/forge.rs`.
- `SpendResources` computes both amounts before paying either: `EnergyCost.GetAmountToSpend()` and `max(0, GetStarCostWithModifiers())`; then `SpendEnergy` (with `AfterEnergySpent`), then `SpendStars`: `LastStarsSpent = amount` always, `LoseStars` and `AfterStarsSpent` only if positive. The paid stars are `ResourceInfo.StarsSpent`/`StarValue`. (C17) `Models/CardModel.cs:1807-1845`, `GameActions/PlayCardAction.cs:93-101`
- An auto-play sets `LastStarsSpent` (all stars for X, else `max(0, GetStarCostWithModifiers())`) before the card is put in the Play pile, so a card in no pile skips `ModifyStarCost` there; `StarValue` is read after, `StarsSpent` is 0. (C17) `Commands/CardCmd.cs:103-129`
- `GetStarCostWithModifiers`: X returns all stars; a card in a combat pile folds `ModifyStarCost` (skipped for a negative cost, guarded); otherwise `CurrentStarCost`, the last temporary cost (a 0 on a card without a star cost keeps -1). Temporary costs are `max(cost, 0)`. `UpgradeStarCostBy` has no floor and drops temporaries above the lower base. ## Batch pile moves (PF5)
- `CardPileCmd.Add(cards, pile, Bottom)` moves the cards one by one, then runs the second loop of `AfterCardChangedPiles` (`CardPileCmd.cs:373-545`). For cards that are all already in combat piles, listed once each, to a pile other than the hand, the first loop calls no hook (`AfterCardEnteredCombat` is only for a card with no pile), draws no random number (only `Random` positions do) and redirects nothing (only a full hand does). Taking each card out of its pile and appending it leaves every other pile in order and the target as its remaining cards followed by the batch, so the engine moves such a batch at once (`CombatState::move_to_pile_bottom`; Shuffle and the end-of-turn flush). The second loop is unchanged. (PF5)
