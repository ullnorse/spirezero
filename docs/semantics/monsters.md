## Weak encounters and generic hooks (C2)
Paths are under `ref/decomp/MegaCrit.Sts2.Core.`.
- An encounter's own `Rng` is `new Rng((ulong)((long)runSeed + TotalFloor) + xxh64(Id.Entry))`, created in `GenerateMonstersWithSlots` right before `GenerateMonsters`. (C2) `Models/EncounterModel.cs:254-266`
- The referee's forced `enter_room` right after `start_run` has `TotalFloor == 1` (the Neow point is already in the map history): only that value reproduces the `SlimesWeak` compositions of seeds `D1S0..5`. `CurrentMapCoord` there is unknown; nothing in scope reads `Monster.Rng`. (C2, observed)
- `SlimesWeak` draws first small slime, second small slime (a `NextItem` over a one-item list still draws), then the medium one, and spawns them small, medium, small. (C2) `Models.Encounters/SlimesWeak.cs:47-58`
- Monsters are created (HP on `Rng.Niche`, `Monster.Rng`) in `CombatRoom.StartCombat` before `SetUpCombat`, so before the deck shuffle; `Monster.Rng = new Rng(runSeed + col + row + CurrentActIndex + CombatId)` with the coord 0 when there is none. The player is attached first (`CombatId` 0); Osty is created through the same `CreateCreature`. (C2) `Rooms/CombatRoom.cs:194-227`, `Combat/CombatState.cs:233-247`, `Commands/PlayerCmd.cs:244-263`
- The unique-HP roll removes other enemies' max HP from an ascending `HashSet`; .NET `HashSet` removal keeps the remaining entries in insertion order, so the candidates stay ascending. (C2) `Entities.Creatures/Creature.cs:372-384`
- With no encounter slots, `SortEnemiesBySlotName` compares every pair as equal (`IndexOf` is -1 for all). .NET's introsort uses `SwapIfGreater`/insertion sort for up to 16 items, which never move equal items, so spawn order is kept. (C2) `Combat/CombatState.cs:496-502`
- Listener order verified: allies are the player then pets appended by `AddCreature` (`_allies.Add`), then enemies, so Osty's powers come between the player's cards and the enemies. (C2) `Combat/CombatState.cs:411-470,535-548`
- `RollMove` transitions immediately when the current state is a branch, even before the first move: a monster whose initial state is a `RandomBranchState` (`LeafSlimeS`) draws `MonsterAi` at combat start; a `ConditionalBranchState` opener (`Nibbit`) resolves then without a draw. The `StateLog` holds the initial state only if it is a move, then each move reached by a roll. (C2) `MonsterMoves.MonsterMoveStateMachine/MonsterMoveStateMachine.cs:22-90`
- `RandomBranchState.GetNextState`: `max = Sum(weights)` (LINQ, `f64` accumulator), `num = NextFloat(max)`, then `num -= w` in `f32` for every branch in order, zero weights included, picking the first with `num <= 0`. A branch weighs 0 if `UseOnlyOnce` and in the log, or if the log's last `n` entries are all it (`CannotRepeat` n=1, `CanRepeatXTimes` n=`maxTimes`), or if it is among the last `cooldown` moves. (C2) `MonsterMoves.MonsterMoveStateMachine/RandomBranchState.cs:115-185`
- `AddBranch(state, 2)` is `CanRepeatXTimes` with `maxTimes` 2 (an `int` literal other than 0 does not convert to the enum). (C2) `Models.Monsters/TwigSlimeM.cs:41`
- A monster's `NextMove` is `UNSET_MOVE` until the first `RollMove`; afterwards it is always the machine's current state. (C2) `Models/MonsterModel.cs:240,416-419`
- `ShrinkPower` is a debuff with `AllowNegative`; `ShrinkerBeetle` applies -1 (infinite, never ticks), it multiplies the owner's powered attack damage by `(100 - 30) / 100 = 0.7`, and it is removed when its applier dies. As a debuff on a player it gets `SkipNextDurationTick`. (C2) `Models.Powers/ShrinkPower.cs`, `Commands/PowerCmd.cs:148-150`
- `PowerCmd.Apply` runs `BeforeApplied`, adds the power, then `AfterApplied` and `Hook.AfterPowerAmountChanged` (only for a non-zero amount); `ModifyAmount` fires `AfterPowerAmountChanged` only when `(int)offset != 0`; `PowerCmd.Remove` is not guarded and calls `AfterRemoved`. `Kill` calls `AfterRemoved` for each power removed after death. (C2) `Commands/PowerCmd.cs:100-330`, `Commands/CreatureCmd.cs:556-561`
- `Slimed`: status, cost 1, `TargetType.None`, Exhaust, draws 1. Slimes add it with `AddToCombatAndPreview` to the bottom of the discard pile (nothing if the player is dead; `AddGeneratedCardsToCombat` does nothing unless combat is in progress). (C2) `Models.Cards/Slimed.cs`, `Commands/CardPileCmd.cs:281-322,1214-1252`
- The referee's `target_index` indexes the living enemies, and its trace lists `CombatState.Enemies`, which a killed enemy leaves. (C2) `referee/vendor/sts2-cli/src/Sts2Headless/RunSimulator.cs:1017`, `referee/tracer/TraceDump.cs:65`
- `AfterRoomEntered` runs over run-level listeners without the combat (deck cards, relics, potions), after `SetUpCombat` and before combat start. `AfterCombatVictory` runs after the per-player teardown (powers and piles cleared). (C2) `Rooms/CombatRoom.cs:220-226`, `Hooks/Hook.cs:1128`, `Combat/CombatManager.cs:1297-1326`
- Referee loadout (`set_loadout`, T5): cards are created with `RunState.CreateCard` and added with `Deck.AddInternal` (`+N` calls `UpgradeInternal`/`FinalizeUpgradeInternal`, which `CardCmd.Upgrade` wraps); starter relics are removed silently with no `AfterRemoved`; each new relic goes through `RelicCmd.Obtain`, so `AfterObtained` runs; potions go through `PotionCmd.TryToProcure` into the first free slot. HP is set last so it overrides a relic's max-HP change. `Commands/RelicCmd.cs:31-52`, `Commands/PotionCmd.cs:28-47`, `Commands/CardCmd.cs:267-285`, `Entities.Players/Player.cs:452-470,628-660`
- RNG effect of loadout relics (observed, seed `T5S0`): `AfterObtained` hooks that use `Rng.Niche` (e.g. `WarPaint`'s `StableShuffle`) advance that stream before the room is entered, and monster HP is rolled on `Rng.Niche`, so the enemy's HP moved 56 -> 57 while the combat shuffle order was unchanged. `PandorasBox` also changes the deck, hence the shuffle. Relics without an RNG-using `AfterObtained` (e.g. `Anchor`, `BoundPhylactery`) change nothing. (T5) `Models.Relics/WarPaint.cs:20-29`, `Runs/RunRngSet.cs:83`

(P1) `Models.Powers/FrailPower.cs`, `Models.Powers/SlipperyPower.cs`, `combat/commands/hp.rs:23`, `combat/commands/damage.rs:178-238`

## Overgrowth normals batch 2 (P3)
Paths are under `ref/decomp/MegaCrit.Sts2.Core.`.
- `ArtifactPower` returns 0 from `TryModifyPowerAmountReceived` for any debuff applied to its owner (`GetTypeForAmount(amount) == Debuff`: a negative amount of an `AllowNegative` counter power is a debuff, a negative amount of a non-negative debuff is a buff) and uses one stack in `AfterModifyingPowerAmountReceived`. `CubexConstruct` gains 13 Block (`ValueProp.Move`) then 1 Artifact in `AfterAddedToRoom`; its blast moves and Charge Up each give itself 2 Strength. The random policy applies no debuff to it, so Artifact's negation is not exercised by the 30 seeds. (P3) `Models.Powers/ArtifactPower.cs`, `Models/PowerModel.cs:468`, `Models.Monsters/CubexConstruct.cs`
- `ConstrictPower` deals `Amount` unpowered damage (dealer = owner) in `AfterSideTurnEnd` when the owner's side ended, and is removed when its applier dies (`AfterDeath`, not prevented). `SlitheringStrangler` opens with Constrict (3), then a random branch (weights 1, both `CanRepeatForever`) over Thwack (attack, 5 Block) and Lash (attack), each followed by Constrict; its secondary enemy is `NextItem` over `[SnappingJaxfruit, MediumSlime, SmallSlimes]`, then the slime picks (small slimes picked twice with replacement). 30 seeds cover all three. (P3) `Models.Powers/ConstrictPower.cs`, `Models.Monsters/SlitheringStrangler.cs`, `Models.Encounters/SlitheringStranglerNormal.cs`
- `SnappingJaxfruit` repeats Energy Orb (attack, +2 Strength); `SnappingJaxfruitNormal` spawns it before a `Flyconid`. 30 seeds match. (P3) `Models.Monsters/SnappingJaxfruit.cs`, `Models.Encounters/SnappingJaxfruitNormal.cs`
- BLOCKED `FogmogNormal`: the Fogmog's first move is `CreatureCmd.Add<EyeWithTeeth>(CombatState, "illusion")`, a mid-combat enemy spawn (new creature, slot name, `SortEnemiesBySlotName` over the encounter's `Slots`, `AfterCreatureAdded`, `PrepareForNextTurn`, `AfterAddedToRoom`), which the engine lacks (`add_osty` is the only creature creation); `EyeWithTeeth` also needs `IllusionPower` (revive through `SetMoveImmediate` with `MustPerformOnceBeforeTransitioning`), `MinionPower` and the `Dazed` status card. (P3) `Models.Monsters/Fogmog.cs`, `Models.Monsters/EyeWithTeeth.cs`, `Models.Powers/IllusionPower.cs`, `Commands/CreatureCmd.cs:38-80`, `Combat/CombatState.cs:496-502`

(P3) `Models.Powers/TangledPower.cs`, `Models.Afflictions/Entangled.cs`, `Commands/CardCmd.cs:617-673`, `Models/CardModel.cs:1508-1541`

## Mid-combat spawns, Fogmog and Vine Shambler (C6)
Paths are under `ref/decomp/MegaCrit.Sts2.Core.`. Both encounters below are unblocked (they were BLOCKED in P3).
- `CreatureCmd.Add<T>(state, slot)` creates the creature (`CreateCreature`: unique-HP roll on `Rng.Niche` against the enemies in combat, so a fixed-HP monster still draws once; the next `CombatId`; `Monster.Rng`), adds it to `Enemies`, runs `SortEnemiesBySlotName` when it has a slot, then `AfterAddedToRoom`, a first `RollMove` only if it is the player's side, and `Hook.AfterCreatureAddedToCombat` (unguarded). `PrepareForNextTurn(rollNewMove: false)` only refreshes intents. (C6) `Commands/CreatureCmd.cs:38-81`, `Combat/CombatState.cs:233-248`, `Combat/CombatManager.cs:1096-1132`
- `SortEnemiesBySlotName` compares `Slots.IndexOf(slot)` (-1 for no slot), so a slotless enemy sorts before any slotted one. Only `NibbitsNormal` (`front`, `back`) and `FogmogNormal` (`illusion`, `fogmog`) have slots among the ported encounters; the Fogmog spawns in `fogmog`, so its `EyeWithTeeth` lands before it in `Enemies`. (C6) `Combat/CombatState.cs:496-502`, `Models.Encounters/FogmogNormal.cs`
- A spawned monster sets `SpawnedThisTurn`, so one added during the enemy turn (Fogmog's Illusion) does not act until the next enemy turn; the enemy turn iterates a snapshot of `Enemies` anyway. (C6) `Entities.Creatures/Creature.cs:713-720`, `Combat/CombatManager.cs:1414`
- `Fogmog`: Illusion (summon `EyeWithTeeth`), then Swipe (8, +1 Strength), then a random branch Swipe (0.4) / Headbutt (0.6, 14), both `CannotRepeat`; the random Swipe goes to Headbutt, Headbutt to Swipe. `EyeWithTeeth` (6 HP) applies `IllusionPower` in `AfterAddedToRoom` and repeats Distract (3 `Dazed` into the discard pile). 30 seeds match, and every one of them exercises the revive. (C6) `Models.Monsters/Fogmog.cs`, `Models.Monsters/EyeWithTeeth.cs`
- `IllusionPower.AfterApplied` adds `MinionPower`, whose `OwnerIsSecondaryEnemy` makes the eye secondary. On its owner's death it forces `REVIVE_MOVE` (`SetMoveImmediate`, `MustPerformOnceBeforeTransitioning`, follow-up the last logged move); the owner stays in `Enemies` (`ShouldCreatureBeRemovedFromCombatAfterDeath` false), is not hittable while reviving, and the revive heals it to full. `SetMoveImmediate` does not log; the roll after the revive logs the follow-up. While an illusion is in combat, every dying creature keeps its non-debuff powers (`ShouldPowerBeRemovedOnDeath` does not check the power's owner). (C6) `Models.Powers/IllusionPower.cs`, `Models/MonsterModel.cs:421-433`, `MonsterMoves.MonsterMoveStateMachine/MoveState.cs:27-70`
- `KillWithoutCheckingWinCondition`: when a primary enemy dies and every living teammate is secondary, those teammates are killed too (`Kill`, after the dead enemy's powers are removed); `IsPrimaryEnemy` is read before the powers go. (C6) `Commands/CreatureCmd.cs:562-573`
- `VineShambler` opens with Swipe (6 x2), then Grasping Vines (8, then 1 `TangledPower` on each target), then Chomp (16), and cycles. 30 seeds match. (C6) `Models.Monsters/VineShambler.cs`
- `IllusionPower.ShouldPowerBeRemovedOnDeath` removes a Debuff only when it is not an `ITemporaryPower` (`TemporaryStrength`/`Dexterity`/`Focus` subclasses, e.g. `EnfeeblingTouchPower`), so a dying `EyeWithTeeth` keeps its `ENFEEBLING_TOUCH_POWER` (and the -Strength it applied) through the revive; the power then removes itself at its owner's side's turn end. Loadout `f2-enfeebling_fogmog` covers it. (F2) `Models.Powers/IllusionPower.cs:59-66`

(P10) `Models.Monsters/BygoneEffigy.cs`, `Models.Powers/SlowPower.cs`
- `Byrdonis` gets `TerritorialPower` (+`Amount` Strength at the end of its side's turn); Swoop then Peck (3 hits), alternating, Swoop first. (P10) `Models.Monsters/Byrdonis.cs`, `Models.Powers/TerritorialPower.cs`
- `PhrogParasiteElite`: slots `phrog`, `wriggler1..4`; one `PhrogParasite` spawns in `phrog` with `InfestedPower` (amount 4, a buff). Infect (3 `Infection` into the discard pile) and Lash (4 hits) alternate. On the Phrog's own death `InfestedPower.AfterDeath` adds four `Wriggler`s with `StartStunned` in `wriggler1..4` (the owner's powers are still there during `AfterDeath`; the spawned wrigglers keep the "kill secondary teammates" check from firing since they are alive and primary), and `ShouldStopCombatFromEnding` is true. A stunned Wriggler opens with `SPAWNED_MOVE` (nothing), then `INIT_MOVE` picks by slot: Nasty Bite (1, 3) or Wriggle (2, 4: 1 `Infection`, +2 Strength); Bite and Wriggle alternate. (P10) `Models.Monsters/PhrogParasite.cs`, `Models.Monsters/Wriggler.cs`, `Models.Powers/InfestedPower.cs`
- `Infection`: status, Unplayable, `HasTurnEndInHandEffect`; deals 3 `Unpowered | Move` damage to its owner (dealer = the owner, card source = the card) when the turn ends with it in hand. `Wound`: status, Unplayable, nothing else. (P10) `Models.Cards/Infection.cs`, `Models.Cards/Wound.cs`, `Commands/CreatureCmd.cs:99-121`
- `Vantom`: `SlipperyPower` 8 (9 from ascension 8) in `AfterAddedToRoom`; Ink Blot, Inky Lance (2 hits), Dismember (attack, then 3 `Wound`), Prepare (+2 Strength), in a cycle. `ShouldDisappearFromDoom` is read only by `DoomPower.PlayVfx` (animation), so it has no effect. (P10) `Models.Monsters/Vantom.cs`, `Models.Powers/DoomPower.cs:104-127`
- `TheKinBoss`: slots `slot1`, `slot2`, `leaderSlot`; `KinFollower` (`StartsWithDance` on the first) x2 and the `KinPriest`. Followers have `MinionPower`; the priest's `AfterDeath` and `AllFollowerDeathResponse` only play music and a speech line. Followers cycle Quick Slash, Boomerang (2 hits), Power Dance; the priest cycles Orb of Frailty (1 Frail), Orb of Weakness (1 Weak), Beam (3 hits), Ritual (+Strength); both orbs apply their debuff with `PowerCmd.Apply` over the targets. (P10) `Models.Encounters/TheKinBoss.cs`, `Models.Monsters/KinFollower.cs`, `Models.Monsters/KinPriest.cs`
- `CeremonialBeast`: Stamp (applies `PlowPower` 150, 160 at ascension 9, to itself), then Plow (attack, +2 Strength) forever. `PlowPower.AfterDamageReceived`: when the owner lost HP and is left at `HP <= Amount`, it removes the owner's `TemporaryStrengthPower` instances (`EnfeeblingTouch` in scope) and then its `StrengthPower`, calls `CreatureCmd.Stun(Owner, ..., "BEAST_CRY_MOVE")` and removes itself. `Creature.StunInternal` builds a new `MoveState("STUNNED")` with `MustPerformOnceBeforeTransitioning` and `FollowUpStateId = nextMoveId` (the last logged move if null), set with `SetMoveImmediate`; it is not logged, and the beast's own `STUN_MOVE` state is never entered. The second phase cycles Beast Cry, Stomp, Crush (+Strength). Engine: `ForcedMove::Stunned` + `monsters::stun`. (P10) `Models.Monsters/CeremonialBeast.cs`, `Models.Powers/PlowPower.cs`, `Entities.Creatures/Creature.cs:525-545`, `Commands/CreatureCmd.cs:922-956`, `Models/MonsterModel.cs:421-433`
- `RingingPower` (debuff, `Single`): `AfterApplied` and `AfterCardEnteredCombat` afflict every card without an affliction with `Ringing`; at the end of the owner's side's turn it removes itself (`AfterRemoved` clears every `Ringing`). `ShouldPlay` (manual and auto plays alike, the play type is ignored) vetoes a `Ringing` card once a `CardPlayStarted` entry of this turn exists for the owner's player. (P10) `Models.Powers/RingingPower.cs`, `Models.Afflictions/Ringing.cs`
- **Escape and late adds** (C22): `CreatureCmd.Escape` removes every power with `RemoveInternal` (no `AfterRemoved`), runs `BeforeRemovedFromRoom`, and moves the creature to `EscapedCreatures` without death hooks; a second call is a no-op (`CombatState == null`) (`CreatureCmd.cs:609-632`). `CombatState.CreateCreature` rolls HP and takes the `CombatId` at creation; `CreatureCmd.Add(creature)` may come later (`SurprisePower` powers the fat gremlin first) (`CombatState.cs:233-248`, `SurprisePower.cs`). `LagavulinMatriarch.IsShellAwake` (the half-HP "wake") only changes animations; the gameplay wake is `AsleepPower` stunning into `SLASH_MOVE` (`AsleepPower.cs`, `LagavulinMatriarch.cs:130-146`).

- `Toadpole`: front one opens Spiken (+2 Thorns), the other Whirl; Spike Spit applies Thorns -2 to itself before its 3 hits. `SoulFysh`: Beckon (one `Beckon` into the draw pile at a random position, one into the discard pile), De-Gas, Gaze (attack, `Beckon` into the discard pile), Fade (2 Intangible), Scream (attack, 3 Vulnerable). `Beckon` is a playable status (cost 1, no effect) that costs its owner 6 unblockable unpowered HP at turn end.
