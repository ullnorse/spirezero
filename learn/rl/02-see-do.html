Week 1 · Day 2

What the agent sees, and what it may do

An agent is not handed "the game". It is handed a flat array of numbers (the observation) and a list of which action indices are allowed right now (the action mask). Both are design decisions, and SpireZero has already made them.

The idea

Observation. The state is whatever the engine holds. The observation is the slice of it the agent gets to see, encoded as numbers. If something isn't in the observation, the agent cannot condition on it. (The order of your draw pile is hidden in the real game, so SpireZero hides it too.)

Action space and mask. A neural net wants a fixed-size output: "action 0 … action N−1". But a fight's legal moves change every step. The fix is a fixed index space plus a mask: a bitset that says which indices are legal now. The agent only ever picks among set bits. The mask says legal, never good; day 1's random agent proved the difference.

Tick "hide the intent" and ask yourself: could any agent, however clever, learn when to block from that vector? It can't. The information isn't there. Observation design is where a lot of RL projects quietly fail, and it's why SpireZero's observation includes the enemies' intents, computed through the same code path the game's intent display would use.


  
SpireZero's action space: 140 indices

  
The real env has to cover playing any of up to 10 hand cards at any of 8 targets, using any of 6 potions at 8 targets, ending the turn, picking an option in a card choice, and saying "done". Two things to take from the grid. First, most of the 140 cells are dark most of the time: the mask is sparse, and a net's output over it would be mostly ignored. Second, the decode of an index is pure arithmetic (index = hand_slot × 8 + target_slot), so the trainer and the engine can never disagree about what an index means.


  
SpireZero's observation: 972 bytes

Why bytes and not floats, and why no one-hot encodings? Because the engine writes this for 64 or more envs every step and copies it to Python with zero copy. Turning the integers into whatever a network wants (embeddings for card ids, normalised HP) happens in numpy or torch, vectorised over the batch. Keep the hot path dumb.

    The math, gently
    

      
A policy over a discrete action space is usually a softmax over N scores (logits) za:

      
π(a | s) = exp(za) / Σb exp(zb)

      
Masking is done by adding a very negative number to the logits of illegal actions before the softmax, which drives their probability to zero without changing the shape of the network:

      
za ← za + (maska − 1) · 109

      
Partial observability has a name too: when the observation is not the full state the problem is a POMDP. Hiding the intent turned the mini fight into one, and no amount of training fixes a missing input.
