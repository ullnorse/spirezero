Week 3 · Day 11

Your first experiment

A concrete plan with the repo's actual env: establish baselines you trust, write the smallest PPO that can work, log the handful of numbers that tell you whether it is working, and know in advance what the first failures look like. Tick things off; the list is saved.

The idea

The goal of experiment one is not a strong agent. It is a training loop you understand end to end, with a win-rate curve that climbs above the random baseline on real Act 1 fights. Every later experiment is a diff against this one, so it should be small, reproducible and boring.

Step 1 · Build and trust the env

cargo build --profile ffi -p sts2-ffi             # target/ffi/libsts2_ffi.so
python -m unittest discover -s python/tests        # smoke: 1,000 random legal steps, layout, stale-build checks
python python/bench.py 64 20000                    # steps/s from Python; expect a few hundred k

Note the numbers the bench prints: actions, episodes, wins and the observation digest. The Rust driver prints the same ones (cargo run --profile ffi -p sts2-ffi --example ffi_bench -- 64 20000); if they match, Python is reading exactly the engine's bytes.

Step 2 · Baselines on a fixed evaluation set

Decide the evaluation protocol before training anything: a fixed start corpus, a fixed seed, N fights, greedy (argmax) actions. Measure:

  • Random legal (sts2.policy.RandomLegal): about 34% on the default Act 1 starts (18,823 wins in 55,231 fights in the perf logs).
  • Greedy heuristic: cargo xtask sweep --policy greedy plays Act 1 with a hand-written rule; its per-fight win rate is your "a competent simple policy" line, the mini fight's hand-written rule.
  • Episode length for each, so you can spot an agent that stalls.

Step 3 · The smallest PPO that can work

About eighty lines of torch over Sts2PufferEnv. Raw bytes in, 140 masked logits and a value out. This is a sketch to type in and own, not a library to import. Shapes and the GAE/done handling are the parts worth reading twice.

import numpy as np, torch, torch.nn as nn
from sts2 import Sts2PufferEnv

N, T, EPOCHS, MB = 256, 128, 4, 4096
GAMMA, LAM, CLIP, ENT, VF, LR = 0.99, 0.95, 0.2, 0.01, 0.5, 3e-4
env = Sts2PufferEnv(num_envs=N, threads=4)
OBS, A = env.batch.obs_bytes, env.batch.actions            # 972, 140
dev = 'cuda' if torch.cuda.is_available() else 'cpu'

class Net(nn.Module):
    def __init__(self):
        super().__init__()
        self.body = nn.Sequential(nn.Linear(OBS, 512), nn.ReLU(), nn.Linear(512, 256), nn.ReLU())
        self.pi, self.v = nn.Linear(256, A), nn.Linear(256, 1)
    def forward(self, obs, mask):
        h = self.body(obs.float() / 255.0)                 # crude featuriser; day 10 §2 is the upgrade
        logits = self.pi(h).masked_fill(~mask, -1e9)
        return torch.distributions.Categorical(logits=logits), self.v(h).squeeze(-1)

net = Net().to(dev); opt = torch.optim.Adam(net.parameters(), lr=LR, eps=1e-5)
obs, _ = env.reset(); obs = torch.as_tensor(np.array(obs), device=dev); mask = torch.as_tensor(env.action_masks, device=dev)
buf = {k: [] for k in ('obs', 'mask', 'act', 'logp', 'rew', 'done', 'val')}
episodes = wins = 0

for it in range(10_000):
    for k in buf: buf[k].clear()
    for t in range(T):                                     # ---- 1. collect
        with torch.no_grad(): dist, val = net(obs, mask)
        act = dist.sample()
        nobs, rew, done, trunc, infos = env.step(act.cpu().numpy().astype(np.int32))
        for k, v in (('obs', obs), ('mask', mask), ('act', act), ('logp', dist.log_prob(act)), ('val', val),
                     ('rew', torch.as_tensor(rew, device=dev)), ('done', torch.as_tensor(done, device=dev, dtype=torch.float32))):
            buf[k].append(v)
        obs = torch.as_tensor(np.array(nobs), device=dev); mask = torch.as_tensor(env.action_masks, device=dev)
        for i in infos: episodes += i['episodes']; wins += i['wins']
    with torch.no_grad(): _, last_val = net(obs, mask)
    vals = torch.stack(buf['val'] + [last_val]); rews = torch.stack(buf['rew']); dones = torch.stack(buf['done'])
    adv = torch.zeros_like(rews); gae = 0                  # ---- 2. advantages (GAE); done cuts the chain
    for t in reversed(range(T)):
        nonterm = 1.0 - dones[t]                           # env auto-resets, so obs[t+1] after done is a new fight
        delta = rews[t] + GAMMA * vals[t + 1] * nonterm - vals[t]
        gae = delta + GAMMA * LAM * nonterm * gae; adv[t] = gae
    ret = adv + vals[:-1]
    flat = {k: torch.cat(buf[k]) if k != 'val' else None for k in buf}; adv, ret = adv.flatten(), ret.flatten()
    adv = (adv - adv.mean()) / (adv.std() + 1e-8)
    for _ in range(EPOCHS):                                # ---- 3-5. clipped policy loss, value loss, entropy
        for idx in torch.randperm(N * T, device=dev).split(MB):
            dist, v = net(flat['obs'][idx], flat['mask'][idx])
            logp = dist.log_prob(flat['act'][idx]); ratio = (logp - flat['logp'][idx]).exp()
            pg = -torch.min(ratio * adv[idx], ratio.clamp(1 - CLIP, 1 + CLIP) * adv[idx]).mean()
            loss = pg + VF * (v - ret[idx]).pow(2).mean() - ENT * dist.entropy().mean()
            opt.zero_grad(); loss.backward(); nn.utils.clip_grad_norm_(net.parameters(), 0.5); opt.step()
    if it % 10 == 0:
        print(f"it {it} steps {(it+1)*N*T} episodes {episodes} win {wins/max(episodes,1):.3f} "
              f"ent {dist.entropy().mean():.2f} clipfrac {((ratio-1).abs()>CLIP).float().mean():.2f}")
        episodes = wins = 0

Things this sketch gets right that are easy to get wrong: the mask is applied in the logits in both passes; done zeroes the bootstrap value because the env has already reset; advantages are normalised per batch; gradients are clipped. Things it leaves out on purpose: a learning-rate schedule, a separate evaluation pass with argmax actions on the fixed set (add that next; the training win rate includes exploration), checkpoints, and any featurisation.

The math, gently

Two quantities in the log table in symbols. The clip fraction is the share of samples with |rt − 1| > ε; it tells you how often the seatbelt engaged. The approximate KL between old and new policy, estimated from the batch, is mean(log πold(a|s) − log π(a|s)) (or the lower-variance mean((r − 1) − log r)); it tells you how far the policy moved per update, and many trainers stop the epochs early when it exceeds a target such as 0.02.

Entropy of the masked policy is H = −Σa legal π(a|s) log π(a|s); its maximum is log(number of legal actions), which is why "near log(legal count)" is the starting point for a fresh net.
