Week 2 · Day 6

Learning from experience: a Q-learning agent, live

Day 5 estimated Q by rolling fights out from one state. That doesn't scale. Q-learning estimates Q for every state the agent visits, from the fights it is already playing, one small correction at a time. Here it trains in your browser.

The idea

Keep a table: for each state the agent has seen, three numbers, Q(s, Strike), Q(s, Defend), Q(s, End). Play fights with ε-greedy on that table (explore a little, exploit mostly). After every single step, do one update:

Q(s, a) ← Q(s, a) + α · ( r + γ · maxa′ Q(s′, a′) − Q(s, a) )

In words: what I thought this move was worth, nudged toward the reward I just got plus the best I now think the next state is worth. The nudge size is α, the learning rate. The target uses the table's own guess about the next state, so early on it is guessing from guesses. That sounds hopeless, but the terminal steps are anchored to real rewards (+1, −1), and that truth propagates backward through the table, one step per update, until the whole thing is consistent. This is temporal-difference learning, and the intuition "today's guess should match tomorrow's reward plus tomorrow's guess" is the single most important idea in RL.

What to try

  • Defaults. Train. Within a few thousand episodes the coarse agent beats "turtle" and approaches the hand-written rule. Nobody told it to block lethal hits.
  • Blind. Reset, pick "only energy and hand", train. The curve flat-lines near zero. The table is tiny and converges fast, to the wrong thing, because the states it needs to tell apart look identical. No learning rate fixes a missing observation (day 2 again).
  • Exact state. Learns higher, but notice the table size: tens of thousands of rows for a game with two card types. It needs more episodes to fill them. That tension is day 8.
  • α = 0.6. Fast, then jittery: each update overwrites too much of what was known. α = 0.01: smooth and slow.
  • ε = 0. Sometimes fine, sometimes stuck: the table never learns about a move it never tries. Compare with ε = 0.3 and watch the training win rate sit below the greedy win rate: exploring costs fights while you learn.
  • γ = 0.8. Future reward is discounted hard, so a win five steps away is worth 0.85 ≈ 0.33. The agent cares less about the end of the fight. Here that mostly slows learning; in some games it changes what the agent wants.
Where this lives in SpireZero
  • The episode is what crates/sts2-rl/src/envs.rs manages: it ends on win, loss, unported content, an empty mask or MAX_EPISODE_ACTIONS, and auto-resets from the next start. The training loop above is that, with the learner wrapped around it.
  • The featurizer choice in this toy is SpireZero's observation design in miniature: crates/sts2-rl/src/obs.rs chose "every number that matters, as plain integers", the "full" option here, and leaves the bucketing to the network.
  • There is no tabular agent in the repo, and there won't be: no table could index 972-byte observations. That is the point of the next lesson.
The math, gently

Q-learning's target is the Bellman optimality equation applied to one sample transition (s, a, r, s′):

target = r + γ · maxa′ Q(s′, a′)    (just r if s′ is terminal)
Q(s, a) ← (1 − α) · Q(s, a) + α · target

The difference (target − Q(s, a)) is the TD error. It is "off-policy": the max makes it learn about the greedy policy even while behaving ε-greedily. Its sibling SARSA uses Q(s′, a′) for the action actually taken next, and so learns about the exploring policy itself.

With a decaying α and every state-action pair visited infinitely often, tabular Q-learning converges to the optimal Q*. "Infinitely often" is doing a lot of work in that sentence, and the next lesson is about what happens when the table is too large to visit.
